## 任务背景

监管处罚数据是研究公司治理、信息披露质量和证券市场监管效果的重要数据来源。CSMAR 违规处理数据库（RE 库）收录了 1994 年以来沪深两市上市公司的违规及处罚全量信息，字段设计复杂：日期用 `00` 表示缺失、违规类型与违规年度以嵌套分隔符存储、部分字段含多重编码……

这些特征使它成为练习数据清洗和数据管理技能的绝佳素材。本题的重点不是最终的统计结论，而是**亲手把一份结构复杂的原始数据转化为可分析的整洁面板，并将清洗结果以规范格式存储**——清洗和存储本身就是核心训练。

**数据来源**：CSMAR → 公司研究系列 → 违规处理 → 违规信息总表（`STK_Violation_Main`）

**核心训练点**：非标准日期清洗、嵌套多值字段拆分（宽转长）、Parquet 存储、SQLite 建库与 SQL 查询

## 任务二：数据清洗

### 2.1 日期字段处理

总表中 `DisposalDate`（处理决定日期）和 `DeclareDate`（公告日期）存在以 `00` 表示缺失的非标准格式：

```
2024/3/00   →  月份已知，日不详
2024/00/00  →  仅年份已知
```

要求：

- 写一个函数 `parse_date(date_str)`，将含 `00` 的日期字符串转换为 `datetime`，无法解析时返回 `NaT`
- 统计两个字段中含 `00` 的记录数及占比，转换后统计 `NaT` 数量
- 计算 `DeclareDate - DisposalDate` 得到「处理滞后天数」`lag_days`，用直方图展示其分布，说明异常值（如负值）的可能原因

### 2.2 多值嵌套字段拆分（核心难点）

`ViolationTypeID` 和 `ViolationYear` 是最复杂的两个字段，两者一一对应，均以「年度间用分号分隔、同一年度内用顿号或逗号分隔」的方式存储。例如：

```
ViolationYear:    2019;2020;2021
ViolationTypeID:  P2504、P2505;P2599;P2503、P2599
```

**目标**：将一行记录拆分为多行，每行为「一个违规事件 × 一个违规年度 × 一种违规类型」的原子记录：

```
ViolationID  ViolationYear  ViolationTypeID  ViolationType
40216566     2019           P2504            推迟披露
40216566     2019           P2505            重大遗漏
40216566     2020           P2599            其他
40216566     2021           P2503            虚假记载
40216566     2021           P2599            其他
```

参考代码框架（需自行补全逻辑）：

```python
import re

def expand_violation(row):
    years    = str(row["ViolationYear"]).split(";")
    type_ids = str(row["ViolationTypeID"]).split(";")
    
    # 两列长度不一致时如何处理？请说明你的决策
    if len(years) != len(type_ids):
        pass  # 你的处理逻辑
    
    records = []
    for year, tid_group in zip(years, type_ids):
        for tid in re.split(r"[、,，]", tid_group):
            records.append({
                "ViolationID":     row["ViolationID"],
                "ViolationYear":   year.strip(),
                "ViolationTypeID": tid.strip(),
            })
    return pd.DataFrame(records)

main_long = pd.concat(
    [expand_violation(row) for _, row in main.iterrows()],
    ignore_index=True
)
```
