## 一、作业的核心目标

> **一句话概括**：学会选题，学会把问题背景用数据说清楚。

很多人拿到数据就开始跑代码，却从未想清楚：**这份分析是给谁看的？他们面临什么决策？我展示的这些数字能帮他们做出更好的决策吗？**

本次作业训练的不是编程能力，而是**研究敏感性**——能识别哪些问题有价值、值得分析，哪些问题看似热闹却没有实质意义。

一个好的选题需要同时回答三个问题：

```
帮谁做决策？  →  在什么背景下？  →  需要哪些事实？
（决策主体）       （政策/市场环境）     （数据与统计）
```

---

## 二、作业的三个关键问题

在开始任何分析之前，小组须先想清楚并写明以下三点：

### 问题一：帮谁做决策？

这是选题的起点，也是最容易被忽视的问题。同一个话题，面向不同的决策主体，研究问题、数据需求、分析重点会完全不同。

**举例**：以「A 股上市公司现金分红」为话题——

| 决策主体             | 他们面临的决策                             | 因此需要回答的问题                         |
| -------------------- | ------------------------------------------ | ------------------------------------------ |
| 监管机构（证监会）   | 新规覆盖多少公司？政策目标能否实现？       | 有多少公司触发监管门槛？分布在哪些行业？   |
| 机构投资者（基金）   | 新规出台后，哪些股票的投资价值会上升？     | 哪些公司被迫分红后，估值逻辑会改变？       |
| 上市公司（财务总监） | 公司需要调整分红政策吗？调整的代价是什么？ | 我们的现金流能支撑提高分红吗？同行怎么做？ |
| 个人投资者           | 现在持有的股票受影响吗？该买还是该卖？     | 我持仓中有多少公司是「潜在受压」标的？     |

**你们的作业必须在开头明确写出**：这份分析是**为谁**设计的，他们面临什么样的实际决策。

---

### 问题二：政策/背景是什么？

「背景」不是粗略地说「近年来 XXX 受到广泛关注」，而是要像一个分析师一样，把关键的**政策文件、数据事实、时间节点**说清楚。

**好的背景描述应该包含**：

- **核心政策文件**：文件名称、发布机构、发布时间、核心条款（引用原文关键句）
- **政策目标**：政府/监管机构希望实现什么？
- **政策对象**：谁会受到影响？
- **统计背景**：问题有多严重？用数字说话（如：有多少公司长期不分红？比例是多少？）

**反面示例**（不够好）：
> 近年来，证监会高度重视上市公司分红问题，出台了一系列政策鼓励分红。

**正面示例**（好的背景）：
> 2023 年 12 月 15 日，证监会发布修订后的《上市公司监管指引第 3 号——上市公司现金分红》，新增规定：连续三年净利润为正但未进行现金分红、且累计未分配利润超过总股本 30% 的公司，将被纳入重点监管名单，证监会将对其实施约谈等措施。  
> 政策背景：截至 2023 年底，A 股 5300 余家上市公司中，约 XXX 家（占比约 XX%）在近三年均有正利润但从未分红，被称为「铁公鸡」……

---

### 问题三：需要展示哪些统计事实？

有了明确的决策主体和政策背景，分析方向就自然清晰了。

**核心任务**：用描述统计和可视化把「事实」展示清楚。

这意味着：
- 相关的数字有多大？分布如何？（基本统计量、分布图）
- 随时间怎么变化？（趋势图）
- 不同群体之间有什么差异？（分组对比）
- 政策前后有什么变化？（事件前后对比）

**不要急着做回归**。把事实描述清楚，往往比跑一个没想清楚的回归更有价值。后续的回归分析、因果识别等作为**加分项**，不是基本要求。

## 三、选题原则

选题完全自由，没有行业、地域或话题的限制。可以来自你的工作，可以来自你的生活，可以是你一直好奇但没有认真研究过的问题。好的选题往往是你自己真正想知道答案的那个问题。

以下几条原则帮助你判断一个想法是否值得做：

**原则一：问题要落地，有真实的决策主体**

问自己：这份分析是给谁看的？他们会用这个结论做什么决定？如果你想不出一个具体的人或机构，问题可能太抽象了。决策主体可以是你自己、你的公司、你的客户、某个政府部门，或者任何面临真实选择的人。

**原则二：背景要说清楚，不能只是印象**

你选的问题，一定有它存在的背景——某个政策变化、某种市场现象、某段你亲身经历的困惑。把这个背景用数据和事实说清楚，是这份作业最重要的任务之一。「大家都知道 XXX 很重要」不算背景，「XXX 问题的规模是多大、在哪些群体中最突出、近几年有什么变化」才是背景。

**原则三：结论要能用数据支撑，不能靠感觉**

好的选题应该有办法用公开可得的数据来回答。不一定要完美的数据，但至少有一条可行的路径。如果你的问题的答案只能靠主观判断，或者需要完全无法获取的私密数据，就需要重新考虑。

**原则四：意义和可行性要同时满足**

只有意义、没有可行性，是空想。只有可行性、没有意义，是无用功。好的选题同时满足两个条件：值得研究，也能够研究。

### 几个帮助启发灵感的问题

- 你在工作中有没有遇到过「这件事我感觉是这样，但我不知道数据上是不是真的」？
- 你最近做过什么重要决定（买房、换工作、投资），当时你最想知道哪些数据？
- 你所在的行业或公司，有没有某个外界普遍有误解、但你觉得数据可以说清楚的问题？
- 有没有什么社会现象或政策，你一直很好奇「它到底影响了多少人、影响有多大」？

### 常见的偏差（需要避免）

❌ **问题太宽泛**：「分析中国经济」「研究 A 股市场」——没有边界，无法聚焦  
❌ **没有决策主体**：「研究某个规律是否存在」——谁需要这个结论，用来做什么决策？  
❌ **数据完全不可得**：核心数据只存在于某个机构的内部系统，无任何公开渠道  
❌ **结论对任何人都没有实用价值**：重复一个学界已经反复验证过的显而易见的结论  
✅ **好的选题**：问题具体、决策主体真实、数据可以获取、结论对某人有用

## 四、提交内容（两份材料）

### 材料一：分析报告

| 要求     | 说明                                        |
| -------- | ------------------------------------------- |
| 必交格式 | `.md` 或 `.ipynb`（二选一，或同时提交）     |
| 推荐附加 | `.html` 或 `.pdf`（由 Jupyter/Quarto 导出） |
| 字数     | 不限，以说清楚为准                          |
| 内容结构 | 见下方「分析报告框架」                      |

**分析报告框架**（各节顺序可灵活调整）：

```
1. 决策主体与研究目标
   - 这份报告是为谁写的？
   - 他们面临什么决策或问题？
   - 本报告希望帮助他们了解什么？

2. 政策/市场背景
   - 核心政策文件（名称、发布时间、关键条款引用）
   - 政策目标与意图
   - 现有问题的严重程度（用数字说话）

3. 数据来源与处理
   - 使用了哪些数据？从哪里获取？
   - 做了哪些清洗和处理？
   - 构造了哪些指标？

4. 统计事实（核心部分）
   - 描述性统计：规模、分布、结构
   - 时间趋势：随时间如何变化？
   - 分组对比：不同子群体之间的差异
   - 政策前后对比（如适用）
   - 每张图/表后须有 2-3 句文字解读

5. 初步结论
   - 用数据说明：背景中描述的问题有多严重？
   - 政策/决策的主要影响对象是谁？
   - 还有哪些问题没有回答，需要进一步分析？

6. 局限性说明
   - 数据局限、方法局限、结论适用范围

【加分项】
7. 进一步分析（回归、事件研究、预测等）
```

### 材料二：Marp 幻灯片

| 要求     | 说明                                          |
| -------- | --------------------------------------------- |
| 工具     | Marp（VS Code 插件）                          |
| 格式     | `slides.md`（源文件）+ `slides.pdf`（导出版） |
| 展示时长 | **10 分钟**，请严格控制时间                   |
| 页数     | 不限                                          |

**幻灯片的逻辑结构**（与报告一致，但更精炼）：

```
封面 → 我们在帮谁解决什么问题 → 政策/背景（关键数字）
    → 数据与指标 → 核心图表（3-5 张）→ 结论 → 局限与展望
```

> **展示技巧**：幻灯片不是报告的复制，每页只呈现一个核心信息。  
> 把背景数字和图表放在前面——让听众先看到「问题有多严重」，再说你们怎么分析。
